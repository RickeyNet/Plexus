# Security Policy

## Versions

Start with the [latest stable release](https://github.com/RickeyNet/Plexus/releases/latest) when checking whether an issue is current. Reports from older releases or `edge` builds are welcome; include the exact version, image tag, or commit so maintainers can identify the affected build. There is no guaranteed backport schedule.

## Report a vulnerability privately

Use GitHub's [private vulnerability reporting form](https://github.com/RickeyNet/Plexus/security/advisories/new) for Plexus. If the form is unavailable, ask a maintainer for a private reporting channel without sharing details publicly. Do not report suspected vulnerabilities in public issues, pull requests, or comments.

Include the affected version, deployment type, affected component, observed behavior, and potential impact. Share only sanitized evidence: remove credentials, API tokens, session cookies, private keys, and customer or network data. Limit any testing to systems you own or are authorized to test.

Maintainers will review reports privately and may ask for clarification. Please coordinate any public disclosure with the maintainers so users have a chance to apply a fix or mitigation.
